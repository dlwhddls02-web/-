# 고민-중심 리딩 구현 (2026-08-23)

## 결론부터

회의록 결정 그대로 구현 끝났어. 코드 새로 짠 건 거의 없고 — 프롬프트 순서 재구성 + 화면 배치 변경이 전부야. 타입체크·엔진 테스트 25건 전부 통과, 3개 화면 스크린샷으로 확인했어.

## 변경 내용

### 1. 입력 화면 (`saju-web/app/input/page.tsx`)
- 고민 입력란을 일반 텍스트박스 → **주황 강조 카드**로 격상. 제목 "요즘 가장 큰 고민이 뭐예요?" + **[권장] 배지** + 안내문("풀이 전체가 그 고민에 대한 답을 중심으로 나옵니다").
- **재유도 1회**: 고민 없이 제출하면 딱 한 번 패널이 뜸 — "고민 적고 보기 / 그냥 볼게요". 다시 제출하면 그냥 통과. 필수 아님(개발팀 권고·대표 결정대로).
- 안내 문구: "고민 내용은 풀이에만 쓰입니다" — ⚠️ 익명 집계 활용을 시작하려면 개인정보처리방침 확정 후 이 문구부터 갱신해야 함.

### 2. 결과 화면 (`saju-web/app/result/page.tsx`)
- 고민을 입력한 경우: 페이지 제목이 "고민에 대한 답"으로 바뀌고, **리딩 섹션이 만세력 시각자료들보다 위로** 올라감. 리딩 상단에 입력한 고민을 인용 칩("당신의 고민 — '…'")으로 표시.
- 고민 없는 경우: 기존 그대로 (만세력 먼저 → "지나온 길" 리딩).

### 3. 턴1 프롬프트 (`saju-engine/src/freereading.ts` `turn1Prompt`)
- 고민 있을 때 순서 재구성: **① 고민 정면 응답(왜 하필 지금 이 고민인지) → ② 과거 연도 콕 집기(증거) → ③ 고민에 대한 답 매듭**. 마케팅팀 결론("고민이 훅, 과거리딩이 근거") 그대로.
- 고민 없을 때는 기존 과거-선행 프롬프트 유지.

## 검증

- `saju-web` `npx tsc --noEmit` 통과, `saju-engine` 타입체크 + 엔진 테스트 25건 통과.
- Playwright 스크린샷 3장: ①강조 카드 ②재유도 패널 ③고민 우선 결과화면 — 전부 의도대로 렌더.
- 새 프롬프트로 실제 리딩 생성 테스트는 안 돌림 (API 비용). 다음 실유저 생성분부터 자연 적용.

## 남은 것 (다음 작업)

- **hasConcern 결제 기록**: 결정 ②(실결제 이력으로 검증)를 하려면 결제/리딩 저장 시 "고민 입력 여부"를 같이 저장해야 함. Supabase 스키마가 아직 미확정(종인 액션아이템)이라 스키마 만들 때 컬럼 하나(`has_concern boolean`) 넣는 걸로 예약. 지금은 미구현.
- 익명 고민 집계("이 나이대 최다 고민" 류)는 실데이터가 쌓인 뒤 마케팅팀 착수 — 방침 문구 확정이 선행 조건.
