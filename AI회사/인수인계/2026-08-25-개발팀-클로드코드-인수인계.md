## 1. 사고 기록 — 왜 이 규칙들이 생겼나

### 1-1. 치명 버그: 엔진이 계산한 판정이 AI에게 전달되지 않고 있었다

`analysis.ts` 는 신강신약·십신분포·격국을 **정확히 계산하고 있었다.** 문제는 `manseryeok.ts` 가
그걸 **프롬프트에 안 넣었다**는 것. AI는 원국 표만 눈대중으로 보고 신강/신약을 **다시 판정**해야 했고,
실제로 뒤집어 읽었다.

| 항목 | 엔진 계산 | 리포트 서술 |
|---|---|---|
| 신강/신약 | **신강**(세력 50) | "목다화식으로 촛불이 꺼진다" = **신약** |
| 최다 십신 | **식상 3개** | "**인성**이 절대적으로 강한 사주" |

신강↔신약이 뒤집히면 용신이 반대가 되고, 용신은 성격·시기·개운법 전부의 기준점이다.
**명식이 맞아도 리딩 전체가 틀린다.** 실사용자가 "완전히 다 틀리다"고 했다.

→ **수정**: `manseryeok.ts` 에 `[신강·신약 — 엔진 확정]` 블록 추가 + "뒤집지 마라" 지시문.
→ **원칙**: 계산은 계산기가 하고, AI는 해석만 한다.

`manseryeok.ts` 상단 주석에 원래 "요약·태그화하지 않는다 — 재료를 전부 보여주고 해석 포인트는 모델이
고른다"고 적혀 있었다. 레퍼런스 재현 의도였지만, 부작용으로 **엔진의 가장 중요한 계산 결과를 버리고 있었다.**

### 1-2. 과거 사건 단정은 구조적으로 빗나간다

격발년 분포를 재보니 **성인기 전체의 87~89%가 격발년**이었다(3명 실측). 변별력이 거의 없다.
게다가 리포트가 고른 연도는 실제로 **강도 최상위** 연도였는데도 틀렸다.

즉 문제는 "언제"가 아니라 **"그 해에 무슨 일이 있었는지 특정하는 것"** 이다.
같은 `寅申충` 이 이직·이사·연애·건강·돈 중 뭘로 발현될지는 계산으로 알 수 없다.

→ **수정**: `HIT_RULES` — 사건 단정 금지, "어느 자리에 어떤 압력이 걸렸는지"만 단정.
   양비론이 아니라 **발현 형태의 폭**을 밝히는 것이다. 연도·근거·구체성은 그대로 유지된다.

### 1-3. 가독성 실패

리포트 실측: **줄의 47~54%에 한자**, 전문용어 건당 800회 이상. 사용자가 "읽다가 포기할까 생각했다".

원인은 어려운 말을 써서가 아니라 **근거와 해석이 같은 문장에 섞여 있어서**다.
기획서 규칙이 "용어 + 번역을 쌍으로" 붙이게 해서 문장이 두 배가 됐다.

→ **수정**: `READABILITY_RULES` — 본문 한자 금지, 근거는 문단 끝 `▸ 근거:` 줄로 **분리**.
   실측 효과: 본문 한자 1,019자 → **0자**, 원가도 395 → **311원(-21%)**.

### 1-4. 스트림이 조용히 멈춰 무한 대기

마지막 턴이 응답 없이 매달렸다(최장 22분, 2회 발생). 기존 코드는 `stop_reason === 'max_tokens'`
일 때만 재시도했고 **타임아웃이 없었다.** 실서비스면 결제 고객이 무한 로딩을 본다.

→ **수정**: `streamWithWatchdog` — 델타가 90초간 없으면 abort 후 재시도(부분 텍스트는 살려서 이어쓰기).
   크레딧 부족 등 진짜 오류는 그대로 위로 던진다(abort된 경우만 멈춤으로 처리).

### 1-5. 지방 출생자에게 틀린 계산 근거를 보여주고 있었다

`manseryeok.ts` 가 `"진태양시 보정(서울 기준 약 -32분)"` 을 **하드코딩**하고 있었다.
엔진은 출생지 경도로 제대로 계산하는데 **표시만 서울 고정**이었다. 김해 출생자는 실제 -24분인데
화면엔 -32분. **"계산이 맞다"는 우리 핵심 세일즈 포인트를 정면으로 훼손하는 버그**다.

→ **수정**: `saju.correction.longitudeCorrectionMin` 실제 값 사용.

## 2. 변경 내용

### 2-1. `lib/saju/freereading.ts` (핵심)

| 추가 | 내용 |
|---|---|
| `READABILITY_RULES` | 본문 한자 금지 / 십신을 기능으로 번역 / 근거는 `▸ 근거:` 줄로 분리 / 표는 근거 칸만 한자 |
| `HIT_RULES` 1~5 | 사건 단정 금지, 압력 단정, 감정은 강하게, 결핍·과다 최우선, 만 나이 병기 |

| `HIT_RULES` 7 | **관계 유지/정리 판정 금지** (상대 명식 없음을 명시, 폭력 의심 시 1366 우선) |
| `HIT_RULES` 8 | **타인(자녀 등) 건강·운 판정 금지** (아이 명식 없이 진단 불가) |
| `streamWithWatchdog` | 유휴 90초 감시 + 재시도 2회 |
| `generateTeaser` | 무료 티저 (명식 캐시 사용, max_tokens 16000 → 4000) |
| `teaserCliffhanger` | 결제 유도 문구 — **코드 조립, LLM 호출 0원** |

**`teaserCliffhanger` 의 함정**: 다음 격발년을 강도 최대로 고르면 11년 뒤가 뽑혀서 결제 유인이 죽는다
(실제로 2037년이 뽑혔다). `강도 ÷ √연차` 로 가까운 해에 가중치를 준다.

### 2-2. `lib/saju/mingsik-cache.ts` (신규)

- 키 = 4기둥 + 성별 + 시간모름여부 + `TEASER_VERSION` (SHA-256, 32자)
- **이름·고민은 키에 안 넣는다** — 넣으면 적중률 0, 개인정보가 키에 노출
- `TEASER_VERSION` 을 키에 포함 → 프롬프트 고치면 **기존 캐시 자동 무효화**
- `hits` 카운터로 적중률 실측
- **프리미엄은 절대 캐싱하지 않는다.** 고민이 리딩 전체의 프레임이라 사람마다 답이 달라야 한다.
  돈 낸 사람에게 남의 고민으로 쓰인 글을 주면 상품 사기다.

**⚠️ 프로덕션 미완료**: 지금은 **로컬 파일 저장**이라 Vercel/Railway에 올리면 배포마다 날아간다.
`lib/store-supabase.ts` 와 같은 패턴으로 Supabase 어댑터를 붙여야 한다.
인터페이스는 `getTeaser` / `putTeaser` / `cacheStats` 3개로 고정해뒀으니 갈아끼우기만 하면 된다.

**적중률 현실 체크**: 명식 공간이 커서(출생연도 1개당 365일 × 12시지 × 성별 2 = 8,760가지)
서로 다른 사람끼리 겹칠 확률은 낮다. 실제 적중은 **같은 사람의 재요청**(새로고침·뒤로가기·재시도)에서 나온다.
원가 절감의 주역은 캐싱이 아니라 **티저 축소**(1,379 → 311원)다.

### 2-3. 무료 구간 설계 변경

**구**: 완결된 과거 리딩 → **신**: 프리미엄 리포트의 실제 앞부분 + 클리프행어

- 구성: 한 줄 서사 → 타고난 구조(결핍·과다) → 지나온 길(압력 2건) → **끊김** → 결제 유도
- 고민은 **무료 프롬프트에 안 넣는다** (캐시 적중률이 0이 되고, 무료에서 답 주면 결제 이유가 사라짐).
  대신 코드가 고민을 인용해 "전체 답은 리포트 2부에"로 연결.
- 전자상거래법 §17⑥ "시험 사용 상품" 요건에 신 설계가 더 정확히 부합(실제 판매 상품의 일부이므로)
- 손익분기 전환율 **17.31% → 4.96%**

## 4. QA — 사람 검수만으로는 못 잡는다

**"그럴듯함"은 신강/신약이 뒤집혀도 유지된다.** 명리 용어가 촘촘하면 읽는 사람은 구분 못 하고,
**자기 얘기가 아닌 걸 아는 당사자만 잡아낸다.** 그래서 자동 검사를 넣었다.

```bash
node scripts/qa-report.mjs <reading-id>
```

검사 항목: 본문 한자 밀도 / 사건 단정 / 금전 단정 / 관계 판정 / 타인 건강 판정 /
**엔진 판정 ↔ 본문 일치**(가장 중요) / 근거 줄 존재

→ **생성 파이프라인에 붙여서 실패 시 재생성하도록 만드는 게 다음 과제다.**
