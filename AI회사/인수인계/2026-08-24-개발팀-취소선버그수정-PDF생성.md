# 취소선 버그 수정 + PDF 생성 (2026-08-24)

## 결론부터

버그는 콘텐츠가 아니라 렌더러였어. 재생성 필요 없이 렌더러 설정 한 줄로 고쳤고, 기존에 이미 만든 리포트 전부(박은혜·김나림·김동원·유하은) 이 수정 이후로는 다 정상 렌더링돼. 그리고 김동원·유하은 리포트를 우리 실제 웹 디자인(챕터 디바이더·카드·콜아웃) 그대로 PDF로 뽑아서 전달했어.

## 버그 원인

`remark-gfm`(마크다운에 GFM 취소선·표 등을 지원하는 라이브러리)의 기본 옵션이 `singleTilde: true`야. 이 옵션이 켜져 있으면 홑물결표(~) **하나만으로도** 취소선의 시작/끝으로 인식해. 그런데 우리 리포트는 "22~31세", "1995~2004"처럼 나이·연도 범위 표기에 홑물결표를 계속 써 — 이게 전부 취소선 구분자 후보가 되면서, 문서 뒤쪽 어딘가의 다른 홑물결표와 멋대로 짝지어져 그 사이 전체 문단에 줄이 그어진 거야. (겹물결표 `~~진짜취소선~~`은 우리가 안 쓰니 이 옵션을 꺼도 상관없음.)

지난번 `**` 렌더링 버그(CommonMark intraword-emphasis)랑 같은 계열이야 — 콘텐츠 자체는 멀쩡한데 마크다운 파서의 기본 옵션이 우리 콘텐츠 패턴(나이·연도 범위 표기)과 안 맞아서 생긴 문제.

## 수정

`saju-web/app/components/ReportView.tsx`, `app/result/page.tsx` 두 곳의 `remarkPlugins`에 `{singleTilde: false}` 옵션 추가. 이게 전부야 — 데이터가 아니라 렌더러 설정이라, **기존에 저장된 리포트 재생성 없이** 다음에 열어보는 순간부터 정상 렌더링돼.

검증: Playwright로 김동원 리포트 페이지 열어서 `getComputedStyle().textDecorationLine`이 `line-through`인 요소를 전체 스캔 — 0건 확인.

## PDF 생성

`saju-web/gen-pdf.mjs` 스크립트 새로 작성 — Playwright로 실제 `/report/[id]` 페이지(챕터 디바이더, 아이콘 배지, 3부 인물·개운 카드, 콜아웃 박스 다 포함된 우리 웹 디자인)를 그대로 열어서 `page.pdf()`로 인쇄. 목차 토글 버튼 같은 인터랙션 UI는 PDF에선 자동으로 숨김.

- 김동원 리포트: 19페이지, 2.4MB
- 유하은 리포트: 비슷한 분량

지금은 로컬 스크립트지만, 나중에 "PDF 다운로드" 버튼을 실제 서비스에 넣을 때 이 스크립트를 API 라우트로 그대로 승격하면 돼 — PHASE3-SPEC에 있던 "PDF 다운로드 미착수" 항목의 절반은 이걸로 끝난 셈.

## 부수 작업 — Supabase readings 테이블 생성

이 작업을 하면서 로컬 파일 저장소로 검증 리포트를 렌더링하려다, 어제 만든 Supabase 프로젝트에 연결이 이미 잡혀 있는데 정작 `readings` 테이블이 없어서 걸렸어. `saju-web/supabase/migration-001-readings.sql`(예전에 미리 작성만 돼 있던 마이그레이션)을 그대로 적용해서 실제 테이블을 만들었어 — 액션아이템에 있던 "readings 테이블 마이그레이션(미구현)" 항목이 이걸로 완료됐어. RLS는 service_role만 접근 가능하게 걸려 있고(마이그레이션 원안 그대로), 실사용자 데이터는 아직 없음(빈 테이블).
