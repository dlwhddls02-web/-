# 리딩 QA

## 왜 자동 검사가 필요한가

**"그럴듯함"은 신강/신약이 뒤집혀도 유지된다.** 명리 용어가 촘촘히 박혀 있으면 읽는 사람은
구분하지 못한다. 실제로 통째로 틀린 리포트가 사람 검수를 통과해 고객에게 전달됐고,
**자기 얘기가 아닌 걸 아는 당사자만** 알아챘다.

## 실행

```bash
node scripts/qa-report.mjs <reading-id>
```

종료 코드: 실패 항목이 있으면 1, 없으면 0 (CI에 걸 수 있다)

## 검사 항목

| 항목 | 기준 |
|---|---|
| **엔진 판정 ↔ 본문 일치** | 엔진이 '신강'인데 본문에 신약·목다화식 서술이 있으면 실패 ← **가장 중요** |
| 본문 한자 밀도 | 근거 줄(`▸`) 제외 본문에 한자 100자 초과면 실패, 30자 초과면 경고 |
| 사건 단정 | "이직했/이사했/합격했/헤어졌/취업했/퇴사했/결혼했/출산했/이혼했" |
| 금전 단정 | "목돈이 들어/성공합니다/부자가 됩니다/빚이 해결됩니다" |
| 관계 판정 | "이혼하세요/헤어지세요/정리하세요/참고 사시면" |
| 타인 건강 판정 | "아이가 아프/자녀가 아프/병에 걸립니다/질병이 있습니다" |
| 근거 줄 존재 | `▸ 근거:` 가 0개면 경고 (가독성 규칙이 안 걸렸을 수 있음) |

## 검사 통과 후에도 사람이 볼 것

자동 검사는 **규칙 위반**만 잡는다. 아래는 여전히 사람이 봐야 한다.

- 나이에 맞는 이야기인가 (만 17세에게 이직·결혼을 말하고 있지 않은가)
- 고민에 실제로 답했는가 (고민 5개를 받았으면 5개가 다 다뤄졌는가)
- 표 안쪽 근거 칸에 한자가 과하게 몰리지 않았는가 (본문 한자 검사는 표를 못 걸러낸다)

## 참고 — 정상 범위 실측값

| 지표 | 정상 |
|---|---|
| 프리미엄 분량 | 25~40페이지 |
| 무료 티저 본문 한자 | 0자 |
| 프리미엄 본문 한자 | 200자 이하 (표 근거 칸 포함) |
| 근거 줄 개수 | 프리미엄 50개 안팎 |
| 사건·금전·관계·건강 단정 | 전부 0건 |

## 검사에 걸렸을 때

1. **엔진 판정 불일치** → `saju-reading` 스킬 규칙 1. 만세력 프롬프트에 확정 판정 블록이
   들어가는지부터 확인한다. 재생성이 필요하다.
2. **한자 과다** → `READABILITY_RULES` 가 프롬프트에 실제로 붙었는지 확인. 표 안쪽이면
   "표는 근거 칸에만 한자" 지시를 강화한다.
3. **단정 표현** → 해당 `HIT_RULES` 항목이 프롬프트에 있는지 확인 후 재생성.

**재생성 비용을 아끼는 법**: 전체를 다시 만들지 말고 `scripts/resume-turn.ts` 로 문제 있는 턴만
다시 만든다. 실측 — 3부만 재생성 1,302원 vs 전체 재생성 5,000~8,000원.
