# 만세력 엔진 — 안전수칙

> 기획서 §7: "여기가 전부의 토대다. 대충 넘어가면 안 된다."
> 절기 초·분 단위 + 표준시 변경 이력 + 서머타임 + 진태양시를 전부 정확히 다루는 오픈소스는
> 확인되지 않았다. **이게 우리의 진짜 해자다.**

## 계산 로직을 바꾸기 전에

1. **테스트 먼저 돌린다.** 엔진 계산 로직 변경 시 테스트 22건 통과가 기본선이다.
2. **유파 논쟁이 있는 항목은 하드코딩하지 않는다.** 전부 옵션으로 뺀다
   (`ziHourMode`, `applyLongitudeCorrection`, `applyEquationOfTime`, `birthLongitude`).
   기본값은 문서화한다.
3. **날짜·횟수 산수는 코드로.** AI에게 계산시키지 않는다.

## 교차검증 — 명식이 의심될 때

`lunar-javascript` 로 대조한다. 단 **CST(UTC+8) 기준이라 시차를 감안**해야 한다.

```bash
npm install lunar-javascript --no-save
node -e "
const {Solar}=require('lunar-javascript');
const e=Solar.fromYmdHms(1995,3,17,16,43,0).getLunar().getEightChar();
console.log(e.getYear(),e.getMonth(),e.getDay(),e.getTime());
"
```

**중요**: `lunar-javascript` 는 진태양시 보정을 안 한다. 우리 엔진과 **시주가 다르게 나오는 게 정상**인
경우가 있다. 실제 사례 — 1993-11-30 09:00 서울 출생:

| | 시주 |
|---|---|
| 보정 없음(다른 앱들) | 辛巳 — 巳시가 09:00 시작이라 |
| 보정 적용(우리) | **庚辰** — -32분 → 08:28이라 아직 辰시 |

이게 랜딩 문구 *"다른 앱이랑 시주가 다르게 나왔을 겁니다"* 의 실제 근거다. 버그가 아니다.

## 명식이 틀렸다는 제보를 받으면 — 이 순서로 좁힌다

1. **양력/음력 확인** — 가장 흔한 원인. 음력을 양력으로 넣으면 월주·일주가 통째로 달라진다.
   `Lunar.fromYmdHms(...).getSolar()` 로 변환해 비교.
2. **성별 확인** — 대운 순행/역행이 뒤집혀 **시기 계산이 전부 달라진다.** 이름만 보고 추측하지 말 것.
3. **출생시간 경계** — 시지 경계 근처면 ±30분에 시주가 바뀔 수 있다. 보정 후 시각으로 확인한다.
4. **교차검증** — 위 방법으로 우리 엔진과 대조.
5. **여기까지 다 맞으면 계산이 아니라 해석 문제다** → `saju-reading` 스킬로 간다.

실제로 "완전히 다 틀리다"는 제보가 **계산이 아니라 해석 문제**였던 적이 있다(엔진 판정이
AI에게 전달되지 않아 신강/신약이 뒤집힌 건). 계산부터 의심하되, 계산이 맞으면 거기서 멈추지 말 것.

## 과거에 실제로 났던 버그

**지방 출생자에게 틀린 근거를 표시**: `manseryeok.ts` 가 `"진태양시 보정(서울 기준 약 -32분)"` 을
하드코딩하고 있었다. 엔진은 출생지 경도로 제대로 계산하는데 **표시만 서울 고정**이었다.
김해 출생자는 실제 -24분인데 화면엔 -32분.

**"계산이 맞다"는 우리 핵심 세일즈 포인트를 정면으로 훼손하는 버그**였고, 계산 정확도를 검증하는
2차 타겟층이 바로 잡아냈을 것이다. 지금은 `saju.correction.longitudeCorrectionMin` 실제 값을 쓴다.

→ **교훈**: 사용자에게 보여주는 근거 문구도 계산값에서 뽑아야 한다. 문구를 하드코딩하지 마라.

## 반드시 처리해야 하는 함정 (기획서 §7-2)

| 함정 | 대응 |
|---|---|
| 1955~60 서머타임 (기저 UTC+8:30 → DST 중 **UTC+9:30**) | tz 테이블에 위임. "-1시간"만 하면 30분 어긋남 |
| 1954~61 표준자오선 127.5° | 항상 135° 기준 계산 (이중 보정 주의) |
| 자정 전환 서머타임 (1948~60) | 일주 경계와 충돌 — 별도 테스트 |
| 존재하지 않는 시각 (1961-08-10 00:15 등) | 명시적 에러 + 사용자 안내 |
| 한중 음력 차이 (1914~2099년 15회) | 음력 입력은 KASI 기반만 |
