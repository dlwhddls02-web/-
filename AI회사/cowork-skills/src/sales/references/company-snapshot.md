- 원칙은 그대로 **오가닉 우선, 유료 광고비 0원**(회사 규칙 §5-2, 재무 로드맵 §1-4). 채널을 4개로 넓힌 건 물량전을 하겠다는 뜻이 아니라, **하나의 소재를 4곳에 리패키징**해서 노출 면적을 늘린다는 뜻이다.
- 소재 재활용 원칙: 콘텐츠 1건 = 숏폼 1개 + 게시물 1개로 만들고, 4채널 규격에 맞춰 자막·길이·해시태그만 바꿔 배포한다. 채널별로 새로 기획하지 않는다.
- 모든 채널의 CTA는 하나로 통일한다 — **무료 미리보기(팔자핏 웹)**. 채널별 다른 제안 금지.
- ⬜ 채널별 실제 유입·전환은 아직 데이터 0. 발행 시작 후 채널별 유입을 반드시 분리 측정한다(어떤 채널이 헛돈지 몰라서 4개를 다 붙들고 있으면 안 됨).

**슬로건 확정 (2026-08-22)**: 메인 "계산 100% + 소름 100%" / 서브 "정확도는 주장하지 않습니다, 증명합니다". ("정확도 200%" 원안은 용용사주 동일 슬로건이라 반려, 변형 채택)

**무료 구간 설계 변경 (2026-08-25 확정)**: 기존 원칙은 "무료 = 과거를 맞혀서 증명(완결된 과거 리딩)"이었으나, **무료 = 프리미엄 리포트의 실제 앞부분 미리보기 + 클리프행어**로 바꾼다.
- 구성: 한 줄 서사 → 타고난 구조(결핍·과다) → 지나온 길(과거 압력 2건) → **끊김** → 결제 유도
- 과거 적중은 그대로 훅으로 쓰되, **사건 단정이 아니라 "어느 자리에 어떤 압력이 걸렸는지"** 로 바꿨다(§3-1)
- 클리프행어("다음으로 크게 움직이는 해는 ○년")는 **코드가 조립**한다 — LLM 호출 0원
- 원가 1,379원 → **311~395원**, 손익분기 전환율 **17.31% → 4.96%**
- 전자상거래법 §17⑥ "시험 사용 상품" 요건에도 신 설계가 더 정확히 부합 (실제 판매 상품의 일부를 그대로 보여주므로)

### 3-1. 2026-08-25 외부 검증에서 나온 것 (실사용자 8명)

하루에 8건(이태경·홍성경·주영은·이아람·유하은·김민석·종인·주영은 건강운)을 실제로 뽑아 지인에게 전달하고 피드백을 받았다. **기획서 Phase 2 완료 조건이던 "지인 10명 실사주 검증"이 사실상 여기서 처음 제대로 돌아갔고, 바로 치명 결함이 나왔다.**

| 발견 | 내용 | 상태 |
|---|---|---|
| **치명 버그 — 엔진 판정 미전달** | `analysis.ts`가 계산한 신강신약·십신분포·격국을 `manseryeok.ts`가 AI에게 **안 넘기고 있었음**. AI가 원국 표만 눈대중으로 보고 다시 판정하다 **신강↔신약을 뒤집어 읽음**(이태경 건). 용신이 반대가 되어 성격·시기·개운법이 통째로 틀림 | ✅ 수정 |
| 과거 사건 단정의 구조적 한계 | 격발년이 전체의 **87~89%**라 변별력이 없고, 같은 격발이 현실에서 무한한 형태로 발현되어 사건 특정은 대부분 빗나감 | ✅ 적중 규칙으로 전환 |
| **가독성 실패** | 리포트 **줄의 47~54%에 한자**가 있었고 전문용어가 건당 800회 이상. 종인이 "읽다가 포기할까 생각했다"고 보고 | ✅ 가독성 규칙 신설 |
| 스트림 멈춤 | 마지막 턴이 응답 없이 매달림(최장 22분). 타임아웃이 없어 무한 대기 — 실서비스면 결제 고객이 무한 로딩을 봄 | ✅ 유휴 감시 추가 |
| 지방 출생자 계산 근거 오표기 | 만세력 화면이 "서울 기준 -32분"을 하드코딩. 김해 출생자에게 틀린 숫자 표시 | ✅ 수정 |

**결과**: 수정 후 재생성한 이태경 건부터 반응이 확연히 좋아졌고, **그걸 본 지인들에게서 문의가 들어오기 시작함**(광고 0원, 오가닉). 이후 홍성경·주영은·이아람도 반응 양호.

**교훈**: "그럴듯함"은 신강/신약이 뒤집혀도 유지된다. 명리 용어가 촘촘하면 읽는 사람은 구분 못 하고, **자기 얘기가 아닌 걸 아는 당사자만 잡아낸다.** 따라서 사람이 읽고 판단하는 검수만으로는 부족하고, **엔진 판정과 본문을 기계적으로 대조하는 자동 검사가 필요하다**(미구현 — 아래 참고).

**아직 안 된 것 (출시 전 필수)**
- **명식 캐시 저장소가 로컬 파일** → Vercel/Railway에 올리면 배포마다 날아감. Supabase 어댑터 필요 (인터페이스는 `getTeaser`/`putTeaser`/`cacheStats` 3개로 고정해둠)
- 엔진 판정 ↔ 본문 자동 대조 검사 (신강인데 본문에 '신약·목다화식'이 나오면 경보)
- 무료 티저 실제 전환율 측정 (데이터 0)

**병행 프로젝트**: 보험설계사용 AI 고지사항 분석 서비스 — 보류 유지 (사주앱 출시 후 재개 여부 결정)

## 5. 전 부서 공통 규칙

1. **확인되지 않은 수치는 만들지 않는다.** 추정이면 "가정치"라고 표시하고 실측 방법을 적는다.
2. **가짜 후기·과장된 약속·가짜 정가 할인 금지.** (표시광고법 + 브랜드 포지션)
3. **사람이 결정할 항목은 따로 표시한다**: 환불·법률·개인정보·가격 변경·외부 공개. `⚠️ 사람 결정 필요` 태그.
4. **사업 아이디어는 대외비.** 외부 서비스에 기획 내용을 올리지 않는다.
5. **바틀/보비 자산 미사용.** 코드·프롬프트·DB·디자인을 참조하거나 재현하지 않는다.
6. **한국 기준.** 법·시장·표현 모두 한국어 사용자 기본값.
7. **말투**: 종인에게는 반말, 결론부터, 짧게. 고객에게 나가는 글은 깔끔한 격식체. 과장 마케팅 톤·AI투·빈말 칭찬 금지. (`voice-style.md`)
8. **품질 기준**: 바로 쓸 수 있을 것, 디자인이 세련될 것, 숫자·사실·맞춤법 오류 없을 것.
9. **애매하면 진행 전에 묻는다.** 단, 질문은 한 번에 모아서.
10. **계산은 계산기가 하고, AI는 해석만 한다.** (2026-08-25 신설) 엔진이 확정한 값(신강신약·십신분포·오행)을 AI가 눈대중으로 다시 판정해서 뒤집으면 안 된다. 확정 판정은 프롬프트에 명시적으로 전달하고, 해석은 그 값을 전제로만 한다. — 이걸 안 지켜서 실제로 리딩이 통째로 틀린 사고가 있었다(§3-1).
11. **읽는 사람은 전문가가 아니라 일반인이다.** (2026-08-25 신설) 고객에게 나가는 사주 글은 **본문에 한자를 쓰지 않는다.** 전문용어는 그것이 뜻하는 기능으로 바꿔 부르고(식상 → 표현하고 밖으로 내놓는 힘), 계산 근거는 문단 끝에 `▸ 근거:` 한 줄로 분리한다. 근거를 없애는 게 아니라 **분리**하는 것이다 — 일반 독자는 건너뛰고, 검증하려는 사람은 그 줄만 보면 된다.
12. **돈·빚·사업 성패는 단정하지 않는다.** (2026-08-25 신설) "몇 년에 목돈이 들어온다", "그 사업은 성공한다", "빚이 언제 해결된다"는 금지. 생계가 걸린 사람이 그걸 믿고 실제 결정을 내리면 해가 간다. 시기의 성격과 행동 지침만 말하고, 부채 고민에는 공적 제도(신용회복위원회 등)를 반드시 함께 안내한다.

## 6. 인수인계 규약 (PDF STEP 04)

앞 팀의 결과물이 다음 팀의 입력이 된다. **요약하지 말고 결과물을 그대로 넘긴다.**

- 저장 위치: `코워크/AI회사/인수인계/YYYY-MM-DD-부서-주제.md`
- 모든 결과물 맨 위에 이 헤더를 붙인다:

```
---
부서: 마케팅팀
날짜: 2026-08-22
입력으로 쓴 것: 인수인계/2026-08-21-대표실-8월우선순위.md
다음 팀: 영업팀
완료 조건: 발행 가능한 콘텐츠 3개 (주제·훅·본문·근거·CTA 포함)
완료 여부: ✅ / ⬜ (미완이면 이유)
사람 결정 필요: (있으면 목록, 없으면 "없음")
---
```

- 완료 조건은 "예쁘게"가 아니라 **수량·형식·마감**처럼 확인 가능한 기준으로 쓴다.
- 기본 흐름: 대표실(기획) → 마케팅·개발(제작) → 영업(판매) → 고객지원(응대) → 운영(자동화) → 대표실·재무(확장 판단)
