# AI 회사 세팅 — 사용법

> PDF "AI 직원 7명으로 회사를 세팅하는 법"을 핫플리케이션(사주앱) 기준으로 옮긴 것.
> 만든 날: 2026-08-21. 이 폴더(`코워크/AI회사/`)가 회사의 본사다.

## 폴더 구조

```
코워크/AI회사/
├── README-사용법.md        ← 이 파일
├── 회사.md                 ← 전 부서 공통 컨텍스트 (목표·규칙·인수인계). 상황 바뀌면 여기만 고치면 됨
├── 인수인계/               ← 부서 결과물이 쌓이는 곳. 앞 팀 → 다음 팀 전달 통로
├── cowork-skills/          ← Cowork용 .skill 7개 (+ src/ 원본)
└── claude-code/            ← Claude Code용 (CLAUDE.md.append, .claude/agents, .claude/commands)
```

## 1. Cowork에 설치 (5분)

`cowork-skills/` 안의 `.skill` 파일 7개를 Cowork 대화창에 하나씩 올리면 파일 카드에 **"스킬 저장"** 버튼이 뜬다. 누르면 끝.
(이 대화에도 7개를 보내놨으니 거기서 바로 저장해도 된다.)

| 스킬 | 부서 | 이렇게 말하면 자동으로 뜸 |
|---|---|---|
| `ceo` | 대표실 | "뭐부터 할까", "오늘 할 일", "스탠드업", "계획 세워줘" |
| `marketing` | 마케팅팀 | "스레드 글 써줘", "랜딩 카피", "훅", "콘텐츠" |
| `sales` | 영업팀 | "DM", "베타 테스터 모집", "제휴 제안", "영업" |
| `support` | 고객지원팀 | "FAQ", "환불 안내", "고객 문의 답변", "공지" |
| `finance` | 재무팀 | "원가", "마진", "비용", "가격 올릴까" |
| `build` | 개발팀 | "만들어줘", "Phase 3", "버그", "배포" |
| `ops` | 운영팀 | "자동화", "반복 작업", "체크리스트", "점검" |

직접 부르고 싶으면 `/ceo`, `/marketing` 처럼 슬래시로.

**중요**: Cowork에서 쓸 때 바탕화면 `코워크` 폴더를 연결해 둬야 부서들이 `회사.md`와 `인수인계/`를 읽고 쓴다. 연결 안 돼 있으면 스킬 안에 든 스냅샷으로 돌아가지만 인수인계가 안 쌓인다.

## 2. Claude Code에 설치 (5분)

사주앱 레포(`saju-engine` 또는 새로 만들 `saju-web`) 루트에서:

```
1. claude-code/dot-claude/ 폴더를 레포 루트로 복사하고 이름을 `.claude` 로 바꾸기  (agents 7개 + commands 3개)
   ※ 보안상 원격에서 `.claude` 이름으로 직접 저장이 안 돼서 `dot-claude` 로 저장해뒀음. 이미 `.claude` 가 있으면 안의 agents/, commands/ 만 합치기
2. claude-code/AI회사/   폴더를 레포 루트로 복사  (회사.md + 인수인계/)
3. claude-code/CLAUDE.md.append 내용을 레포 CLAUDE.md 맨 아래에 붙여넣기
```

Claude Code 안에서 한 줄로: `바탕화면 코워크/AI회사/claude-code 의 dot-claude 를 .claude 로, AI회사 폴더를 루트로 복사하고 CLAUDE.md.append 를 CLAUDE.md 끝에 붙여줘`

레포가 여러 개면 `.claude/`와 `AI회사/`를 각각 복사하되, **`회사.md`는 한 군데(코워크/AI회사/)가 원본**이다. 바뀌면 복사본도 갱신.

쓰는 법:

| 커맨드 | 하는 일 |
|---|---|
| `/plan-month` | 대표실이 이번 달 목표 1문장 + 우선순위 5개 + 부서 배정 |
| `/standup` | 매일 아침. 어제 결과물 점검 → 오늘 할 일 1개 |
| `/handoff` | 방금 결과물을 인수인계 폴더에 저장하고 다음 팀 호출 |

그냥 말해도 된다: "marketing 에이전트로 스레드 3개 만들어" / "build 한테 Phase 3-1 계획 짜게 해".

## 3. 첫날 60분 (PDF STEP 05 그대로)

| 시간 | 할 일 | 명령 |
|---|---|---|
| 00–10 | 회사 목표 확인 | `회사.md` §1 네 칸 읽고 틀린 거 고치기 (이미 채워놨음) |
| 10–20 | 대표실에 우선순위 요청 | Cowork: "`/ceo` 이번 달 세팅해줘" / Code: `/plan-month` |
| 20–35 | 가장 중요한 팀 1개 실행 | 대표실이 찍어준 1번 — 지금 단계면 아마 `build` (Phase 3-1 LLM 연동) |
| 35–45 | 결과물 다음 팀에 넘기기 | `/handoff` — 요약 말고 파일 그대로 |
| 45–55 | 완료 조건으로 검수 | 헤더의 ✅/⬜ 확인. 수량·형식·마감 기준 |
| 55–60 | 내일 반복할 일 저장 | `ops` 에게 "오늘 한 순서 점검표로 만들어" |

**오늘의 성공 기준**: 7명 다 돌리는 게 아니라 부서 하나가 결과물 하나를 끝내는 것.

## 4. 매일 돌리는 루틴 (제안)

- 아침: `/standup` (또는 `/ceo 스탠드업`) → 오늘 1개
- 작업: 해당 부서 1~2개
- 저녁: `/handoff` → 인수인계 폴더에 남기기
- 금요일: `finance` → 이번 주 숫자 3개 / `ceo` 주간 회고 (유지·중단·확대)

원하면 Cowork 스케줄 작업으로 매일 아침 9시 `/standup`을 자동 실행하게 걸 수 있다. `ops`에게 "스탠드업 자동화해줘" 하면 설정 프롬프트를 만들어준다.

## 5. 상황이 바뀌면

- 목표·가격·타겟·하지 않을 일이 바뀜 → `회사.md` §1 수정. 끝. 전 부서가 다음 호출부터 반영
- 프로젝트 단계가 넘어감 → `회사.md` §3 수정
- 새 프로젝트 시작 (보험 AI 등) → `회사.md`를 복사해 `회사-보험.md` 만들고 대표실에 "이번 달은 보험 기준" 이라고 말하기. 부서 스킬은 그대로 재사용
- 부서 역할 자체를 바꾸고 싶음 → `cowork-skills/src/부서/SKILL.md` 고치고 다시 `.skill`로 압축 (Cowork에 "이 스킬 고쳐줘" 해도 됨)
